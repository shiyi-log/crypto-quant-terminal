```python
def _is_archived_taker_account(strategy_id):          # 后缀 "_100x" ⇒ 归档
    return str(strategy_id).startswith("s") and str(strategy_id).endswith(ARCHIVED_VARIANT_SUFFIX)

def _is_active_execution_account(row) -> bool:
```

### 2.1 建议的改动（最小、非破坏性）

**把 `execution_enabled` 的承认范围从"仅实验变体"改为"通用"**，例如：

```python
def _is_active_execution_account(row) -> bool:
    execution = row.get("execution") or {}
    if _is_archived_taker_account(row.get("strategy_id", "")):
        return False
    # ⭐ 新增：通用禁用标志（对 2x2 与普通账户一致生效）
    if execution.get("execution_enabled") is False:
        return False
    if execution.get("execution_variant") == EXPERIMENTAL_EXECUTION_VARIANT:
        return True
    return execution.get("leverage") == EXECUTION_MODEL.get("leverage", 100)
```

**然后对 63 个活跃的目标账户执行**：

```sql
UPDATE quant.strategy_sim_accounts
   SET execution = jsonb_set(execution, '{execution_enabled}', 'false'::jsonb),
       updated_at = now()
 WHERE (strategy_id LIKE 's14_vol_compression_release%'
     OR strategy_id LIKE 's34_vwap_anchor_reversion%'
     OR strategy_id LIKE 's09_trend_pullback%'
```

## 3.5 🔴 独立高优先修复项：「每笔最多亏 50 USDT」当前【不生效】

⚠️ **这不是退役工作，但优先级同样高**（它关系到用户明确声明的约束是否被遵守）。

### 3.5.1 实测（Round 203/204 · 只读）

| 指标 | 值 |
|---|---|
| 有 `max_loss_per_trade_usdt` 的账户平仓笔数 | 3,625 |
| **突破【各自上限】的笔数** | **836（23.1%）** |
| **最差突破倍数** | **4.1×**（`max_loss=50` 账户：−204.7）|

⚠️ **Round 226 更正**：初稿报"44.7% · 48.3 倍"有误 —— 脚本把所有有上限账户统一除以 50，
但 `max_loss` 实为 **50 / 200 / 1000** 三档（与 `R` 变体一一对应）。
正确值：`max_loss=50` → 突破 **28.6%** · 最差 **4.1×**。**结构性结论不变。**

### 3.5.2 根因：该字段不是止损执行

```
strategy_2x2_experiment.py:71/72/86/191/230  → 只做【归一化/传递】
tools/*.py                                   → 只用于 --risk-cap 【筛选账户】
risk_capped_notional() / risk_capped_margin() → 只算【名义仓位】，不是止损
```

它约束的是**仓位大小**（`名义 = f(50, 止损距离)`），不是**实际亏损**。

**按退出原因分解 —— 关键在于两种"止损"完全不同**：

| exit_reason | 笔数 | 均值 | 最差 | 超 50 占比 |
|---|---|---|---|---|
| **`stop_loss_intrabar`** | 48 | **−49.99** | −50.01 | 12.5% |
| **`stop_loss_close_confirmed`** | 883 | **−303.24** | −1,698.75 | **95.8%** |
| `liquidation` | 379 | −389.99 | **−2,415.93** | 87.9% |

⇒ **只有 `stop_loss_intrabar` 精确受 50 约束；`stop_loss_close_confirmed`（收盘确认式）
与 `liquidation` 都不受约束。** 这正是 `strategy_specs.json` 中
`execution_contract.risk_cap.DEFECT_20261012_no_hard_stop` 所记录的缺陷。
