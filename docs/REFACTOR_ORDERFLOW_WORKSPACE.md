# 订单流与价格研究工作区

本节对应 2026-11-16 重构计划 P3。页面只读取现有研究端点；页面完成不代表研究准入、策略上线或 Demo 验收通过。没有新增交易命令、研究写入或真实账户访问。

## 工作区与原功能

- `/quant/orderflow`：以成交额突增事件账本为主面，右侧核对精确事件，窄屏将检查器放到列表之后。保留 BTC/ETH、5m、成熟状态筛选、10/25/50 本地分页、原始成交额/基线/笔数/主动失衡、预热估算、按币种成熟窗口统计。
- 事件检查器展示方法版本、数据指纹、5m/30m/1h/4h 成熟状态、毛收益/MFE/MAE、成熟时间、完整修订时间线及原始 JSON。未知窗口保持未知；最新无效修订清除旧收益，即使嵌套历史结果仍标 matured。
- `/quant/price-spikes`：保留 BTC/ETH、方向筛选、在线候选和有效样本、六档条件概率、无条件提升、基线预热与采样范围。候选账本联动精确检查器；上涨、下跌和未达阈值分别显示，成熟 `none` 不再被误标为下跌。
- t−12 至 t+12 的方向分组量比剖面只用实际提供的点，缺口断线，不插值或补零；保留逐点样本量。2.5 年回顾性参考独立标明来源不一致与收益锚点缺失，不并入在线统计。

两个页面通过 RouterLink 跳转，兼容发布环境 hash router。`event_id` 为精确历史定位参数；不存在、不可读取、范围不匹配时给出未取得状态，不默认换成最近事件。交易对、状态或方向变化取消旧请求，并用请求代次拒绝迟到的成功与错误，卸载同样使回报失效。

## 读取与证据边界

订单流列表、详情和统计直接读取原始 GET 合同，避免便利 wrapper 将损坏的 `items` 归一为空数组。成功空集、尚未读取、合同损坏、读取失败和保留旧事实分开。失败保留上次成功列表或统计，并标明成功时间与旧筛选身份，不把旧 BTC 事实显示为新 ETH 事实。响应事件与查询交易对、周期、状态绑定；详情同时绑定事件 ID。

统计允许缺失指标显示未知；错误类型、负计数、错误预热布尔、无效时间及重复币种不能成为成功统计。预热 ready 只展示来源的明确布尔值，最后一根延迟时不计算乐观完成时间。价格接口严格核对实际 close3 方法、futures/5m、方向、在线样本范围、六档与统计元数据。

当前在线来源仅 BTC/ETH 和 5m。基线使用前 288 根已完成 K 线成交额中位数，当前根不参与；分档为 2x、4x、8x、20x。现有突增成熟窗口 5m/30m/1h/4h 和价格的后续 3 根收盘 15 分钟口径各自保留，均不能改名为计划中未来 1/5/15/30/60 分钟的新研究结果。TRX、多周期、新标签、完整盘口序列、费用/资金费、真实成交率、逆向选择、bootstrap/HAC 与多重比较仍需后端证据。20 档快照不证明全市场挂单数、撤单量或队列位置。
