# 量化终端前端设计契约

日期：2026-11-23  
状态：设计基线，后续按 P3 小节逐页实现并校验  
适用范围：Vben Vue 3 / TypeScript 工作区；本轮所有交互继续使用固定本地演示数据。

## 目标与使用场景

面向需要同时确认环境、风险、订单状态和研究证据的量化交易操作员。打开应用后的首要问题不是“今天赚了多少”，而是“当前看的是哪个环境、数据是否新鲜、现在是否允许增加风险”。所有收益和账户数值在演示环境显式标记为样例。危险动作的原型只能说明确认步骤，不连接账户、不写服务端、不发送交易命令。

## 视觉变量

| 角色 | 色值 | 用途 |
| --- | --- | --- |
| 深海底色 | `#0C1B2A` | 全局画布、固定导航 |
| 海图工作面 | `#132B3E` | 主工作区、菜单浮层 |
| 声纳分隔线 | `#29485C` | 表格横线、区域边界、焦点轮廓底 |
| 雾白正文 | `#E5EDF4` | 标题、关键数值、正文 |
| 潮汐次文 | `#A2B8C9` | 时间、来源、解释文字 |
| 声纳蓝 | `#69B4E4` | 当前导航、选中态、键盘焦点 |

盈利/亏损/注意采用绿色 `#49C7A5`、红色 `#F27F78`、琥珀色 `#E8B65C`；所有方向和状态同时使用文字与图标，不只依赖颜色。颜色只表达环境、层级、方向或风险，不能作为装饰渐变。

## 字体与数字

- 中文界面：思源黑体优先，系统无字体时回退到 `PingFang SC`、`Noto Sans CJK SC` 与无衬线系统字体。
- 英文和行情数字：IBM Plex Sans，按 tabular numerals 对齐价格、数量和损益。
- 订单号、哈希和运行日志：IBM Plex Mono；普通小字不滥用等宽字体。
- 标题左对齐；数值表格右对齐；解释性正文左对齐，行宽尽量不超过 80 个汉字。

## 桌面信息布局

桌面端采取“窄导航 + 主作业面 + 风险证据侧轨”。身份和环境固定在页面顶部；风险侧轨用连续刻度表达剩余风险、冷却或硬失败，避免把风险信息隐藏在可折叠卡片中。核心行情和表格占据最大面积。

```text
1440 × 900
┌──────────────┬─────────────────────────────────────┬─────────────────┐
│ 产品/导航    │ 环境：Binance Demo   样本时间/质量 │ 风险状态与刻度  │
│ 交易台       ├─────────────────────────────────────┤ 冷却/硬失败     │
│ 研究         │ 主标题 / 当前交易对 / 周期          │ 风险预算余量    │
│ 验收         ├─────────────────────────────────────┤ 保护与数据证据  │
│ 数据         │ 主图或核心指标                       │ 事件/状态说明   │
│ 运维         ├─────────────────────────────────────┤                 │
│ 设置         │ 明细表、成交或研究结果               │                 │
└──────────────┴─────────────────────────────────────┴─────────────────┘
```

顶栏和导航左对齐，时间、价格与表格数字按列对齐。研究页允许更宽的主画布；操作事件与样本来源沿用侧轨位置，让每个工作区共享相同风险坐标，而不强行复用相同的卡片栅格。

## 移动端信息布局

移动端优先回答环境、风险、持仓和状态。将导航收成可键盘/触屏操作的底部工作区入口；主图和明细表拆成有标签的视图切换，避免横向滚动整页或压缩到无法阅读的表格。风险状态始终位于标题下方且先于长表格。

```text
390 × 844
┌──────────────────────────┐
│ 量化终端      Binance Demo │
├──────────────────────────┤
│ 风险：冷却中  剩余 18 分钟 │
│ 样本时间 / 数据质量        │
├──────────────────────────┤
│ BTCUSDT       15 分钟       │
│ 图表 | 持仓 | 委托 | 事件   │
├──────────────────────────┤
│ 当前视图内容               │
│ 可读行项目，单列滚动       │
├──────────────────────────┤
│ 交易台  研究  验收  更多    │
└──────────────────────────┘
```

## 设计原则

1. 环境和证据先于表现：演示样本、缺失值、过期数据和未知状态必须常驻可见。
2. 用刻度与分隔表示工作关系：行情、风险和订单具有明确层级，禁止把整页切成外观相同的卡片墙。
3. 保留交易语义：命令受理、成交、保护确认和对账分别展示，不合并成“成功”。
4. 错误和空状态给出下一步：指出缺什么证据或如何恢复读取，不写营销文案，也不自动清除失败状态。
5. 仅用动作触发的短反馈表达状态改变；尊重 `prefers-reduced-motion`，键盘焦点清晰可见。

## 对设计简报的复核

本产品已有明确的深海蓝、中文金融终端和风险常驻要求，因此不另换浅色营销页风格，也不采用通用的近黑底配荧光绿。视觉焦点选为侧边的“声纳风险刻度”：它把剩余风险、冷却时间和硬失败位置映射到同一纵向轴上，服务具体操作任务。其余区域保持平实表格、细分隔线和一致对齐，避免重复渐变、装饰标签与卡片阴影。

## 逐页实施顺序和验收

逐步改造交易台、验收与上线、因子/订单流、策略、实验任务、数据中心、运维证据和设置系统页。每页需有正常、空、未知、过期、失败、部分成交、冷却和硬失败中适用的状态；数据来源均由本地固定样例承载。每个页面切片独立写中文开发台账、变更记录、测试与运行日志，使用中文提交消息并推送；稳定后才移除相应旧页面入口。桌面 1920/1440、平板 768、手机 390 纳入真实生产构建页面检查。
