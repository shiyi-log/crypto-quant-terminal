# 历史迭代工作区

迭代路由仍由 iteration/index.vue 提供，入口现在以四个分区组织既有历史功能：运行队列、走查分析、版本登记和研究证据账。分区使用条件挂载；离开的页面卸载自身轮询器，回到运行队列时仍按 URL 的 run_id 精确恢复目标。

运行队列将执行状态与研究裁定分开显示。详情必须匹配请求中的 run_id；非法或重复身份、损坏结构及失败响应不会覆盖已知列表快照。费用和冻结证据缺失时保持未知，旧运行不会被静默替代。

走查分析保留原来的迭代结果、参数与风险、深度学习和参考四个子页，以及各自的数据表。它只读取迭代摘要与深度学习状态；请求失败或格式不完整时保留最近成功快照，首次失败不伪装成空数据。错误提示不传出请求异常内容，组件卸载后忽略迟到响应并清除定时器。

版本登记独立读取版本注册表。登记是显式人工命令：登记理由必填，未通过冻结判据时需要单独确认，确认目标在提交期间冻结，重复提交受阻，回执状态和版本 ID 必须核对。成功只说明注册表登记，不代表部署或交易授权。

研究证据账继续分别呈现研究账本与前视观察。两个来源的失败或损坏刷新保留各自最后成功快照，并隐藏异常和内部诊断细节；离开分区时停止自动刷新。

定向验证命令：

- pnpm --dir vben exec vitest run --dom apps/web-antd/src/views/quant/iteration/__tests__
- git diff --check -- vben/apps/web-antd/src/views/quant/iteration docs/REFACTOR_ITERATION_HISTORY.md

全应用类型检查、构建和浏览器验收由集成任务统一执行。
