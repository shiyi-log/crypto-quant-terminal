# 量化终端六周开发计划

## 目标与当前基线

计划周期为 **2026 年 11 月 16 日至 12 月 27 日，北京时间**。目标是交付可在本机持续运行、数据统一存放外盘、研究结果可复核、故障可恢复的量化终端。

本轮覆盖前端、后端、数据库、运维，以及现有自动迭代、回测和模拟验证链路。以工程可靠性和研究证据完整性作为验收依据；策略是否通过，继续遵守各自冻结的研究判据。

本次只读核查确认：

- 核心服务健康接口均返回 HTTP 200，但完整性检查近期出现查询超时，数据报告同时存在过期、缺口和空数据集，需要按实际用途重新核验。
- 回测包装器存在“进程成功退出、结果为空，进度仍显示完成”的路径；界面部分服务检测仍指向旧迭代入口。
- PostgreSQL 已运行在外盘目录，模型、结果、缓冲、交易 SQLite 和日志仍需统一迁移；当前内盘约剩 **29 GiB**，外盘约剩 **630 GiB**。
- CI 已运行 pytest 和数据库集成测试，后续重点是补齐迭代链路测试、前端业务单测和发布检查。
- 当前全套测试尚未重跑，旧规划中的失败数量不作为本轮基线。

## 实施方案与接口变化

### 运行管理与外盘迁移

- 以仓库内服务定义和 `manage.py` 为唯一管理入口，家目录启动脚本改为调用该入口。统一维护服务期望状态、进程身份、心跳和最后错误；暂停、故障重启与业务门禁分别处理。
- 新增统一配置 `QUANT_DATA_ROOT`，指向 `/Volumes/yidong/quant-terminal-data`；历史归档继续使用 `/Volumes/yidong/quant_archive`。迁移行情文件、模型、回测结果、运行缓冲、SQLite、日志及运行证据，已有目标目录通过清单核验后复用。
- 保留现有 PostgreSQL 容器及挂载方式，运维入口明确识别外部管理数据库，避免执行本地 cluster 初始化而产生第二套数据库。
- 采用“在线预复制 → 等待当前任务安全边界 → 暂停单个写入服务 → 最终一致性复制 → 切换路径 → 验证并恢复”的顺序。训练任务等待本轮完成，SQLite 使用在线备份及最终短暂关闭写入；不同时停掉全部服务。
- 每次切换保留文件指纹、数据库完整性结果、切换时间及回退位置。切换后已经产生新数据时，回退必须携带新增数据，不能直接恢复旧副本。旧副本在验收完成前保留。
- 检查外盘挂载身份和可写状态；挂载失效时禁止在同名本地目录继续写入。原有相对路径通过兼容映射读取，Git 中的冻结历史证据保持可追溯，后续运行写入迁至外盘。

### 数据完整性与恢复

- 将数据集标记为“持续更新”或“历史冻结”，记录来源、交易对、周期、字段要求和预期更新时间。原生 K 线与重采样数据分别标识。
- 实时完整性检查按数据集和时间窗口增量执行，历史全量检查分批进行；单个数据集超时需要报告失败，不能使整轮报告消失。
- 收盘采集独立于浏览器运行。K 线按交易所能力补取，逐笔和盘口无法重建的区间明确保留缺口，不用插值伪装完整数据。
- 增加 `manage.py db backup`、`manage.py db restore` 和文件快照能力，输出清单与校验值。恢复默认进入隔离目标；日常保留最近两份验证通过的数据库备份，文件快照保留七天，并预留恢复空间。
- 运维页面展示采集、同步、归档、完整性检查各自的更新时间和错误，避免把“同步完成”显示成“全部数据健康”。

### 回测、迭代与研究证据

- 每次运行使用独立 `run_id` 和结果目录。结果必须匹配策略、模型、有效配置、数据指纹及时间区间；不再从公共目录选取最新 ZIP。
- 缓存结果只有在身份完整匹配时才可复用，并记录缓存来源；无法证明匹配时重新计算。只有结果解析和归档成功后才能标记运行完成。
- 将执行状态与研究结论分开：执行状态描述运行、成功、失败、取消；研究结论描述通过、拒绝或不可评估。候选收益不达标仍保留完整证据。
- 每轮保存配置快照、代码与数据指纹、结果文件哈希、关键指标、判据版本和失败原因，注册表引用该轮不可变产物。
- 为研究账本补齐数据库层禁止修改和删除的保护；修订通过追加事件表达。沿用各研究协议的样本与成本要求，执行口径变化使用新身份和独立观察记录。

### API、前端与交付

- 新增只读接口 `GET /api/locals/iterations` 和 `GET /api/locals/iterations/{run_id}`，提供运行列表、进度、结果来源、研究判定及证据引用；同步增加前端类型定义。
- 扩展现有服务与运维接口，分别返回期望状态、进程状态、业务更新时间、健康原因及存储状态。旧接口保留兼容，迭代页面切换到新接口。
- 优先完善总览、数据中心、回测任务、模型迭代和运维页面；明确区分历史回测、纸面观察、模拟盘、执行失败和样本不足。
- CI 加入迭代包装器契约测试、前端业务单测，以及锁定交易/FreqAI 依赖的离线测试任务。发布流程必须验证待交付提交 SHA 对应的 CI 成功结果。

## 测试与最终验收

- **回测与迭代：**覆盖新结果、合法缓存、错误缓存、无结果、损坏结果、并发其他任务产物、非零退出、零交易和非有限指标；验证失败结果不能被误登记为通过，自动迭代不会提升当前使用版本。
- **数据与迁移：**覆盖外盘未挂载、空间不足、重复迁移、复制中断、SQLite 活跃写入、监督器误重启和切换后回退；迁移前后核对文件指纹、交易记录、持仓与研究事件连续性。
- **数据质量：**覆盖历史冻结集、实时超期、重复收盘、跨周期边界、断线补取、接口限流和不可恢复盘口缺口；重复执行补取不得重复入账。
- **恢复与交付：**在隔离数据库恢复真实备份，核对关键表数量、最新时间、研究事件及抽样业务查询；运行后端与数据库测试、前端单测、类型检查、构建和冻结身份检查。
- **七天观察：**界面状态与实际任务一致；所有超期和缺口有记录；有效研究轮次均有可复核产物；日志及缓冲容量受控；关键操作流程无阻断错误。

## 已确定的边界与默认安排

- 交付环境为当前 Mac，本轮围绕现有研究链路和模拟盘完善功能，新增策略机制与公网部署放到后续阶段。
- 迁移优先保持在线，允许单个写入服务在一致性切换时短暂中断；不承诺交易 SQLite 路径切换完全零中断。
- 备份使用现有外盘，本轮恢复能力覆盖误操作和数据损坏；整盘故障恢复需要后续增加独立备份介质。
- 研究门槛保持原有冻结定义，六周工程验收不以产生盈利策略为条件。R11、TrendFollowing 等项目未达到各自判定条件时继续观察。
- 按一个主开发执行者协调、子任务并行审查估算。若迁移或数据修复超出预期，优先顺延页面美化和大型重构，保留数据一致性、回归测试及恢复演练。
- 本轮交付包含代码、测试、运行手册和验收记录；开发台账统一维护每项工作的状态、证据和剩余问题。
