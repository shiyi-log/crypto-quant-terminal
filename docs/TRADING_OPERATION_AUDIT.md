# 交易操作与收益归因验收记录

## 请求审计

认证代理对强制开平仓、撤单、删除交易、启动、停止、暂停买入、重载配置等写请求，先把 `trading_operation_requested` 提交到 PostgreSQL 的 `research_ledger_events`，再发送上游请求。审计不可写时返回 503，请求不会发送。只读查询不产生操作审计。

结果记录为 `trading_operation_result`，以同一个 `request_id` 关联。字段包含认证账户、请求 UTC 时间、来源地址、动作、目标交易、HTTP 状态和结果分类。请求体只提取有类型约束的业务字段，令牌、密码、Authorization、任意文本和原始响应不落库。

- `accepted`：API 接受请求，不能据此认定成交。
- `rejected`：明确的 HTTP 或业务拒绝。
- `unknown`：超时、断连、服务端错误，或没有结果记录。
- `not_forwarded`：请求没有发往上游。

超时不自动重试交易。上游已响应但结果审计写入失败时，界面收到“可能已执行，请勿重复提交”的错误和请求编号；先核对订单。认证账户不等于可证明的自然人身份。

研究证据账同时展示最近操作审计。覆盖范围是认证代理；直接访问机器人 API、Telegram 或其他入口不能据此认定已完整审计。过去缺少日志的事件不能补造操作者。

## 账户与策略表现

实际交易保留原始 `exit_reason`。账户总收益包含所有明确已平仓交易；策略归因汇总、外部干预、未知离场分别展示。`force_exit` 不计策略表现，但不会从账户收益中消失。止损、ROI、移动止损和强平属于策略执行或风险结果，不能只因它们不是突破退出就排除损失。

已经成交的外部退出订单可以证明部分干预，即使最终交易的离场原因后来被策略退出覆盖。未成交订单不能当作已发生的干预。缺失订单标签或方向的覆盖限制必须披露，不猜测利润分摊。未知收益保留 `null`，已知小计与缺失笔数单列。

## 已作废研究结果

旧巡检接口返回 `legacy_disabled` / `invalidated`，实时检查为空，旧记录仅留档。已知旧注册表的年化、夏普、实现偏差和通过判据采用失效投影，原值留在 `legacy_metrics` / `legacy_gate`，不改写历史文件。`champion` 登记不能证明运行时部署，更不能证明实际收益。

## 订单展示编号

当前持仓、最近成交和订单详情使用 `YYYYMMDD-HHMMSS-币种-交易所原始订单号`，时间统一为北京时间。无时区的 Freqtrade 日期按 UTC 解读，再转换为北京时间。交易所原号和内部交易 ID 保留；数据库主键、API 路由、撤单和平仓目标仍使用原始 ID。缺失字段明确显示未知，不使用当前时间或内部交易 ID 代替。

## 验证与生效范围

验证覆盖请求提交顺序、存库失败阻断、HTTP 和业务拒绝、超时未知、有限的 401 令牌刷新、结果写入失败、敏感字段过滤、真实隔离 PostgreSQL 事务以及收益分类。验收不调用真实交易写接口。

认证代理及前端发布后，代理审计与账本展示立即生效。机器人直连访问日志使用独立配置 overlay，详见 [API_ACCESS_LOGGING.md](API_ACCESS_LOGGING.md)；现有交易进程不为本次改动重启，该日志在下一次正常加载配置后生效。
