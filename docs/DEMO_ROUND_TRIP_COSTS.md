# 完整往返交易的实际成本证明

本模块为 P1 离线协议切片。`demo_round_trip_costs.reconcile_round_trip_costs(evidence, previous_completions=None)` 不访问数据库或交易所，返回不可变 `RoundTripCostReport`；`to_dict()` 返回独立副本。所有结果均为 `production_wired=false`、`acceptance_eligible=false`。它不能认证调用者归档的真实性，也不替代账户独占、唯一 writer、原生保护或人工批准。

## 输入与完整性

顶层必须提供 Demo 环境、账户、阶段、策略版本和轮次，以及代码、策略、执行、风险和成本五个 SHA-256。`opening` 必须是精确起点的已归档空仓、完整普通/条件订单事实；`coverage` 必须来自已归档账户对账，并明确连续起止窗口、全部收入类型、成交和订单覆盖。每个订单、成交、现金流及换算证据都绑定相同身份和 `source_ref/source_hash`。这些标志仅作为内部归档协议输入，HTTP 自报标志不能用作可信来源。

支持 BTC、ETH、TRX 的单向 `BOTH` 仓位。每个成交必须存在相同币种、方向、客户端与交易所订单身份；逐单成交数量之和严格等于订单累计成交量，且订单终态明确。全成状态要求累计成交等于原始数量。减仓成交的订单必须 `reduce_only=true`，加仓订单必须 false。未完成仓位不产生完整交易；同一入口跨多个回零周期不能拆成多笔，反向穿仓也不能拆成两笔。

金额只接受有限十进制字符串、整数或 Decimal，拒绝 float、bool、超界位数和指数。计算使用独立 1024 位精度上下文，规范化不调用会按全局精度舍入的 `normalize()`。数量、金额、实际净收益均返回十进制字符串。

## 净收益与资金费

固定计算：

`净收益 = 已实现盈亏 - 实际手续费（USDT） + 有符号实际资金费 + 有符号其它确认支出`。

实际成交价格已经包含真实滑点，任何计划滑点字段都不再次扣减。成交中的已实现盈亏和手续费与归档现金流逐笔核对；对应现金流只证明一致性，不二次计费。`TRANSFER` 永不计入交易收益。其它支出仅接受显式 `OTHER_COST` 且金额非正，必须绑定实际成交；未知收入类型阻断。

手续费缺失、冲突、转换不明或实际盈亏缺失时，净收益为 null，且不生成风险事件。非 USDT 手续费需要匹配成交、资产、金额、时间与原始归档的明确换算。负手续费默认拒绝；只有冻结 `verified_exchange_rebates` 政策、实际成交返佣确认和正向返佣流水一致时才可纳入。

资金费按同币种实际持仓时段精确分配一次。空列表只有完整全类型覆盖才表示零；缺少扫描证据仍为未知。若资金费与任意成交同毫秒，必须有相同归档事件流、严格单调的事件顺序及完整截至该点的成交 ID 序列，核算持仓数量必须一致。单独 `ordering_verified=true` 或自报仓位不足以授权归属。同毫秒跨两笔已闭交易若无法唯一定位则拒绝。未闭持仓资金费留在 `open_positions.pending_funding_usdt` 与交易 ID 清单，不冒充已完成净收益。

## 身份、重放与修正

`trade_id` 和 `event_id` 只绑定账户/阶段/策略/轮次、币种和有序真实成交 ID；费用补记不会创建第二笔交易身份。另一个 `proof_sha256` 覆盖本笔经济事实、冻结版本、实际归档引用和完整性结论。更大的全局扫描窗口、新增无关入金或其它交易不会改变旧笔经济证明；当前扫描引用仍单独返回供审计。

调用方应从不可改写完成账提供 `trade_id → proof_sha256`。相同证明重放标记 `already_recorded=true`，不产生第二个风险事件。相同身份而证明不同输出 `completion_correction_required`，净收益不可用于风险计数，必须由修正流程处理。纯函数不能证明调用者提供了完整旧账，也不写入该账。

完整交易结果包含验收所需的 `opened_at/closed_at/closed/costs_included/funding_complete/fill_reconciliation_complete/net_pnl_usdt`，并提供与 `DemoRiskPolicy.record_round_trip` 参数相符的 `risk_event`。只有受信任持久层在同一账户锁与幂等事务内审查并落账后才能接线。

## 尚未接线

实际账户、成交与完整现金流归档采集、费用转换来源核验、完成事件不可改写存储、成本修正工作流、三连亏调用、权威验收 API 均由后续切片处理。不得把本模块离线通过当作真实账户或 30 天验收通过。日志只包含完成状态、数量和稳定原因码，不输出账户凭据、原始响应或上游异常文本。

同一币种同一毫秒的多条成交必须具备同一归档事件流和互不重复的顺序号，并按该顺序重放；没有权威顺序时保持不可评估。增加仓位的成交不得声明非零已实现盈亏，拒绝状态的普通订单不得含任何成交。整组归档遇到结构性错误时，已计算交易的嵌套事件也被清除，调用方不能从失败批次取出一笔风险事件。

手续费和已实现盈亏收入必须不早于关联成交；允许更晚确认和补记，但不能把早于实际成交的收入借作本笔证据。输入时间不能替代完整归档来源的权威核验。
