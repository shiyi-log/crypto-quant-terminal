# 旧 Freqtrade 交易视图改造说明

旧 `overview`、`positions` 与 `market` 路径继续服务原有 Freqtrade 账户，均显式标记“旧 Freqtrade 交易引擎”。这些路径与 Binance Demo 的权益、持仓、盈亏及风控裁定分开；旧选币白名单只用于浏览旧引擎行情，不构成新账户可交易范围。模拟/实盘标签只在 `show_config.dry_run` 是实际布尔值时显示，缺少或形状异常时环境为未知。

总览以旧引擎当前持仓账本和来源检查器为主。余额、盈亏、策略、因子、任务、服务、选币名单、持仓和成交独立读取；一项失败保留其上次成功快照和时间，其余来源仍可更新。首次读取失败、损坏响应、空数组以及真实空数组分别显示为未知、读取失败或确认为空。金额只使用可验证的数值，持仓合计任一金额缺失时报告未知。交易编号链接保留实际 Freqtrade `trade_id`，详情导航不会替换成另一笔交易。

顶部旧引擎命令均为显式用户动作，并使用二次确认。启动可能开始扫描或开新仓；停止也停止管理已有仓位；暂停买入仍继续管理已有仓位；重载会丢弃运行期配置；全部退出显式提交市价 `tradeid=all`。旧引擎环境、持仓计数或状态未能核实时相应操作禁用。命令回执描述为“已提交”或“待查询核验”，不等同交易所成交。

持仓详情继续显示原始交易号、原始订单号、订单状态和费用字段；行级市价退出、限价退出、部分退出、撤单、交易所重载和自定义数据仍保留。撤单不改变持仓；退出命令提交不等于已平仓。旧引擎退出接口仅在退出数量严格小于已知持仓数量时按部分退出处理，因此拒绝等于或超过整笔持仓数量的部分退出请求。删除交易 API 只会移除本地交易记录，不会平仓并会破坏审计快照，因此“删除记录”从正式持仓工作台退役。手工 API 或维护操作仍可能造成的数据缺口应保持可见，不能误说交易已退出。

市场视图维持旧选币集合、仍持仓的交易对及 5m、15m、30m、1h、4h、1d、1w 浏览范围。应清楚标识实时公共行情、服务端本地 OHLCV 回落数据及旧策略周期 K 线，失去实时连接时不得把旧数据称为直播行情；具体留存与选择交互见 market 工作区报告。

## 验收边界

- 单项旧接口失败不会清空其他上次成功的事实；响应形状损坏不会变成空持仓、零余额或零任务。
- 不自动启动、退出、撤单、重载或清除历史记录。
- 错误展示固定中文，不回显 URL、数据库诊断或上游自由文本。
- 新请求不会被切换前尚未完成的结果覆盖，卸载后的请求不再更新页面状态。
- 总览仅呈现旧引擎事实及明确注明的历史监控，不能替新交易台计算授权、风控余额或验收资格。
- 市场、持仓页各自有独立完成报告；这一说明不代替统一构建与多宽度浏览器验收。
