## 1. 币安的机器人产品线（官方产品，UI 层）

| 机器人 | 机制 | 我的收入来源拆解 |
|---|---|---|
| **现货网格** | 在区间内挂 N 个限价单；下穿买单成交、上穿卖单成交 | 格配对利润（买低卖高各一格） |
| **合约网格** | 同上，但有杠杆；三种模式：做多 / 做空 / **中立** | 同上，但方向性暴露被杠杆放大 |
| **DCA / 定投** | 按时间或跌幅定期买入 | 无（是建仓工具，不是策略） |
| **再平衡** | 按目标权重定期调仓 | 无 alpha，是风险管理工具 |
| **资金费率套利** | 现货多 + 永续空（或其他组合），赚资金费 | 资金费 − 两腿成本 |
| **信号机器人** | 接收 TradingView webhook 下单 | 取决于外部信号 |
| **跟单** | 复制他人交易 | 取决于被跟者 |

**⚠️ API 探测事实**：`/sapi/v1/gridTrading/*` 在 `api.binance.com` 返回 **404**
（端点不存在）→ **网格机器人没有公开 API**，只能在 UI 操作。
而 `/sapi/v1/dci/*`、`/sapi/v1/copyTrading/*` 存在但需签名。

## 2. 网格的数学（严格）

### 2.1 每格利润

```
每格净利 = 格距 − 2 × 手续费
```

用本会话实测的成本（第 69 轮修正：BTC maker 往返 **4.024 bp**）：

| 格距 | 每格净利 | 能否覆盖成本 |
|---|---:|---|
| 0.04% (4 bp) | **0 bp** | 恰好持平 |
| 0.1% (10 bp) | **+5.98 bp** | ✅ |
| 0.5% (50 bp) | **+45.98 bp** | ✅ |
| 1.0% (100 bp) | **+95.98 bp** | ✅ |

**⚠️ 关键区别**：格距是**人为设定**的，不是市场给的。
所以网格的「单格边际」远大于我实测的动量边际（0.83 bp）——
**这不是因为网格有 alpha，而是因为它把波动率切成了人为大小的块。**

### 2.2 严格的期望分解

```
P&L = Σ(格配对利润) + 持仓方向性盈亏 − 成本
恒等式：网格 ⟺ 做多波动率 / 做空趋势
```

| 价格过程 | E[网格 P&L] |
|---|---|
| **几何布朗运动（无漂移随机游走）** | **≈ 0 − 成本** ⇒ **负** |
| **均值回归** | **> 0** |
| **单边趋势** | **大幅亏损**（尾部风险） |

**⇒ 网格的正期望【完全依赖均值回归的存在】。**

### 2.3 用我们的数据检验「震荡 vs 趋势」

路程/漂移比 = Σ|ΔP| / |P_end − P_start|（>5 表示震荡为主）：

| 币 | 15m | 1h | 1d | 判读 |
|---|---:|---:|---:|---|
| BTC | 306.6 | 151.5 | 33.1 | ✅ 震荡为主 |
| ETH | 2486.4 | 1304.4 | 62.6 | ✅ 震荡为主 |
| TRX | 125.7 | 66.4 | 19.5 | ✅ 震荡为主 |

**表面结论：震荡远多于趋势 → 网格有大量配对机会。**

### 2.4 但代价（尾部风险）

| 币 | 最大单边回撤 | 最坏连续下行（日） |
|---|---:|---:|
| BTC | **−76.7%** | 8 |
| ETH | **−79.4%** | 8 |
| TRX | **−69.6%** | 7 |

**⇒ 网格在单边下行中会累积这个量级的浮亏。合约网格则有强平风险。**

## 3. ⚠️ 最关键的一步：网格依赖的正是已被否证的机制

```
网格的正期望 ⟺ 均值回归存在
⇒ 而本会话已【三源否证】1H/15m 的均值回归机制：
   · 我的复算：15m 毛边际 0.83 bp < 成本 4.02 bp
   · 项目自有研究：5m/15m 机制 50 组参数全部净负
   · 外部独立 kill list：「同信号在 1D 有效、1H 亏 75%」
⇒ 【网格所依赖的均值回归，恰好是被否证的那一个】
```

**⚠️ 但这不构成对网格的完整否证**，理由有三：
1. 网格用的不是「预测信号」，而是「无条件挂单」——**机制不同源**
2. 网格的每格利润（10~100 bp）远大于被否证的边际（0.83 bp）
3. 我上面的「均值回归被否证」针对的是**基于 K 线的预测信号**，
   而网格的均值回归利用是**被动做市**，两者的证据不可直接互推

**⇒ 诚实结论：网格是【尚未被本项目严格检验】的方向，
   但它依赖的宏观前提（震荡多于趋势）**部分成立**（路程/漂移比 19.5~2486），
   而它的风险（单边深套）**已被实测证实**（回撤 69.6~79.4%）。**

## 4. ⚠️ 我失败的建模尝试（如实记录）

我尝试三次用 K 线模拟网格，三次都错：

| 尝试 | 错误 | 症状 |
|---|---|---|
| ① 穿越计数 | 网格只覆盖起点 ±20 格 | 穿越 0 次 |
| ② FIFO 配对 | 把**趋势**当成格利润 | BTC 期末浮亏 **4,039%** |
| ③ LIFO 配对 | 用「格线落在 K 线高低点之间」当穿越，但价格可能起止同侧 → 系统性高估 | 1195 次配对 vs 40 格 |

**根本原因**：网格的真实记账需要**逐笔撮合模拟**（限价单成交、排队、区间处理）。
用 K 线高低点近似必然高估穿越次数。

**⚠️ 正确做法（留给实现）**：
1. 用项目的 **10Hz 订单簿**逐笔重放（BTC 209 万 / ETH 215 万快照）
2. 或用**币安官方网格的回测/实盘数据**（但无公开 API，需 UI 导出）
3. 或**直接在 Demo 跑一个网格**（我们有 Demo 能力了）
