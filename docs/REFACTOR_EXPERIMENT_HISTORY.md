# 历史实验工作区

本节对应 2026-11-16 全栈重构计划 P3 的回测监视、实验任务、迭代记录和历史产物详情。页面维持历史研究语义：执行完成不等于研究通过；旧报告数值不证明成本完整，也不构成 Binance Demo、30 日验收或实盘资格。

## 保留的入口与历史能力

- `/quant/backtest` 保留脚本回测、研究实例回测和模型自动迭代的独立事实来源。状态轮询、结果表、平仓归因、最近 trial（包括失败）和累计 trial 仍可查看；页面切换到研究任务或迭代记录时卸载相邻工作区，避免多个历史页面同时轮询。没有当前进度但仍有 trial 时，旧试验记录仍显示。
- `/quant/tasks` 保留研究实例回测、数据下载、前瞻分析和递归分析四类工具；原有策略/币对/周期/时间范围/钱包/缓存/protections 输入，以及下载范围、erase、前瞻阈值和多个 startup_candle 输入仍可操作。命令回执与后台执行状态分开显示；超时或响应损坏按结果未知处理，并在 sessionStorage 持续锁定对应命令。解锁前需手动刷新事实、在研究实例后台核对后勾选确认并输入“接受重复执行风险”；解锁不会自动重发，操作者须再次点击提交。下载、前瞻和递归任务只有后台任务 status=`success` 且 `running=false` 时才被视为执行完成；pending 与 running=false 仍持续轮询。分析接口按真实 `{ status: 'ended', running: false, result }` 合同校验，HTTP 成功封套中的 error、未完成结果或错误结构保留上次成功结果并供刷新后重读同一个精确 job_id。历史回测清单保留精确文件与策略身份、备注读写和时间/周期字段。
- `/quant/iteration` 按运行队列、走查分析、版本登记、研究证据账四个分区组织内容。走查分析保留原四个分析页和结果表；队列按 `run_id` 读取准确运行；版本登记继续要求人工理由和必要确认；研究账与前视观察分别保留来源。切换分区会卸载其刷新任务。
- `/quant/detail` 保留资金曲线、模型预测与实际收益散点、逐笔交易的币对和盈亏筛选、交易决策字段、币对汇总、退出原因汇总及回测阈值。历史摘要明确保留原报告口径，不补算未知成本。

## 身份和证据边界

详情页接受单一 `identifier`、`run_id` 或 `job_id`。`identifier` 对应只读产物目录里的 `models/<identifier>/backtest_detail.json`。`run_id` 读取迭代运行记录；当前服务端投影允许字段中不包含 `identifier`，所以现有迭代 API 实际只能显示运行事实并标明没有可核验的回测产物映射，组件不会把运行编号猜作模型标识。后台分析任务按 `job_id` 读取状态；只有任务明确成功后才读取前瞻/递归结果，不根据执行完成生成研究通过结论。冲突、重复、非法或未知查询参数拒绝读取其它目标；请求切换后的迟到响应不覆盖新目标。

实验任务的磁盘历史回测合同提供 `filename`、`strategy` 和 `run_id`，旧回测详情接口则按模型 `identifier` 取值；迭代运行详情又属于单独的自动迭代注册表。当前历史合同没有提供从 Freqtrade 历史字段到旧详情 `identifier` 或自动迭代运行 ID 的可验证映射。历史任务行因此显示映射缺失，不跨注册表跳转。详情目录仍可按其真实 `identifier` 定位。实验运行文件中的 manifests、配置、输入清单和结果摘要也没有统一接入详情查询 API。

删除历史产物不再由正式研究任务页发起，既有磁盘文件保留；当前任务页的 reset 命令仅清理研究实例内存回测结果，不删除磁盘历史文件。任务备注仍可保存；备注成功回执不改变该运行的产物身份或研究裁定。历史页面展示的收益、预测能力或旧判据不跨接到纸面账户、Demo 或实盘证据。

## 验证边界

各页面的定向测试和格式检查随本次实现分别记录在交接状态及开发台账。`DetailWorkspace.test.ts` 覆盖精确身份、非法/重复参数、身份错配、缺失映射、后台任务定位、迟到响应和刷新失败保留；iteration 子目录测试覆盖运行选择、分区卸载、分析快照和登记/账本读写边界。主集成仍须在并行修改稳定后重跑合并定向测试、应用类型检查及生产构建，并完成桌面、平板和手机浏览器验证。组件测试通过不代表路由、布局或 API 在真实服务环境验收完成。
