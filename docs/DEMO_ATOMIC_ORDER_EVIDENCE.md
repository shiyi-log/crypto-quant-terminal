# Demo 普通与条件订单的原子读取证据

本小节提供适配器内部只读接口，不提交订单、撤单或修改账户配置，也不授予
策略准入、原生保护资格或验收资格。

## 调用合同

两个接口保留原调用方式和标准化列表返回值：

    adapter.fetch_open_orders(pair=None)
    adapter.fetch_open_conditional_orders(pair=None)

显式传入 with_evidence=True 时返回与账户采集器一致的两字段封套：

    {
        'data': [...],
        'request_evidence': {...},
    }

with_evidence 只接受布尔值；非法值在网络请求前拒绝。data 仍为原标准化
订单列表，每行 raw 保留去除认证材料后的交易所原文，数量与价格保留十进制
字符串，外来币种及外来客户端订单身份保留。可选布尔值无法确认时维持未知；
算法单触发或结束继续不等于退出成交。

无 pair 时读取全账户挂单，不能以 BTC/ETH/TRX 交易白名单隐藏其它敞口。
指定 pair 时只允许现有交易白名单，并要求所有响应行与请求交易对一致。
真实空列表是合法观察；空对象、非列表、非对象行、非法 symbol 或 scope
不符均报有界安全异常，不当作空账户事实。

## 原子证据与快照隔离

两种读取均复用 _read_archive，在同一实例的请求锁内完成 HTTP、原文验证、
标准化、响应摘要与请求元数据封装。归档调用不得事后读取可变 last_call，
再与另一条响应拼接证据。

request_evidence 包含固定 API、路径、GET 方法、参数、状态、适配器版本、
请求权重、开始/接收 UTC 时间、本机延迟、response_sha256 与摘要基础。
真实受守卫传输提供 raw_http_response_bytes 摘要；离线替身没有原始字节时
只提供 canonical_json 摘要并明确标注，不能冒充真实 HTTP 字节证据。
每次读取前清除上一响应摘要，避免借用旧请求证据。

封套、last_call 与客户端响应中的嵌套结构分别复制。返回值仍是便于归档的
普通字典和列表，调用方可修改自己的副本；这些修改不能改写其它已返回封套、
last_call 或客户端原文。此处“冻结”指一次读取时已完成事实配对和副本隔离，
不是把 Python 容器变成不可变类型。

严格证据模式要求关键订单身份、方向、类型/状态和金额具备有效原始值。
金额只接受有限的十进制字符串或整数，拒绝布尔、浮点、缺失、无穷和负值；
普通单已成交量不能超过原始数量。存在的原始时间必须为非负整数。默认旧
列表调用保留原有可选字段未知语义，同时也拒绝损坏快照形状与 scope 错配。
任何传输失败保持失败，没有自动重试或将失败补成空列表。

## 日志与验证

成功读取只记录固定中文步骤、受限范围、订单数量及是否请求证据封套；不记
账户响应、认证材料、签名 URL 或原始异常内容。现有传输守卫仍负责 Demo
host、明确凭据、只读路径、禁重定向和禁自动重试。

离线回归覆盖：默认列表兼容、外来订单、空/坏形状、scope 错配、金额精度、
异常方向字段、旧摘要清除、秘密剔除、嵌套副本隔离、传输失败与凭据边界。
并发回归在第一条 HTTP 已返回而证据尚未冻结时暂停验证，要求第二条读取
不能进入传输；实际移除请求锁的变异探针会触发失败。该测试验证单实例请求
证据配对，不证明多个 REST 请求构成同一账户原子时点。

## 后续边界

本接口没有证明订单列表覆盖最终性、持仓保护覆盖、午夜权益、现金流完整性、
账户对账或独占 writer。采集器接线、冻结运行 manifest、语义投影、可信
selector 和 API 组合根分别实施；不能因封套存在就把 capability 或
acceptance_eligible 改成 True。正式 Demo 合同和真实原生保护仍待独立验证。
