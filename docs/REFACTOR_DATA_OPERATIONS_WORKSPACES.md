# 数据与质量、运维与证据工作区

本切片执行 `REFACTOR_PLAN_LIVE_TRADING_20261116.md` 的前端工作区重构。新增页面读取已有服务事实，并把尚未接通的研究质量、账户执行资格和恢复证明显示为未知。父级负责路由、导航、构建和浏览器验收。

旧页继续保留，新增页采用独立的数据表、证据检查器和事件视图。历史入口使用 RouterLink，兼容生产的 hash 路由。新增页面没有采集启动、同步、删除、交易升级或批准按钮。

## 数据与质量

数据页通过现有 `ftClient`、运行时 API 地址和会话守卫读取 `GET /locals/database/status`。它校验原始响应，而不是调用会把缺失集合变为空数组的 `getDatabaseStatus` 便利适配器。这样，损坏或缺失的清单不会被显示为“暂无数据”。没有新增接口、固定端口或凭据。

主表精确按交易对与频率筛选，保留交易所、市场和 K 线类型组成的独立身份；所选行的记录数与首末时间在侧栏展示。来源清单显示格式、记录数、更新时间和服务报告的错误。数据库名称与版本可见，连接串和数据库路径不进入页面。

以下四项始终显示“未取得证据”，直到后端有可验证合同：

- 365 天逐频率连续覆盖：需要完整区间、缺口清单及冻结版本；端点跨度和记录数不足以作裁定。
- 闭盘与可用时间：需要 `closed-only`、`available-at` 和时区约束。
- 盘口序列：需要快照、增量序号及断档校验。
- 冻结数据指纹：需要不可变 URI、SHA-256 和质量裁定。

采集或同步进程“运行中”仅表示服务报告的进程状态。它不会改变研究准入或交易执行资格。缺失计数和时间显示“未提供”；显式零仍显示零。带时区的时间统一显示 UTC，无时区的来源时间保留原文并说明时区未提供。

## 运维与证据

运维页读取已有运行健康 `GET /locals/runtime-health`、服务清单 `GET /locals/services` 和研究账本事件 `GET /locals/research-ledger-events`。服务报告与账户资格分别展示：账户身份、唯一写者、风险预算、批准和恢复演练证据没有权威来源时保持未知。服务健康不会使账户允许新增风险。

事件按研究身份读取和筛选，检查器仅展示明确的事件身份、时间、类型和合法哈希字段。原始 payload 不作为全文日志展开。事件端点同样读取原始响应，避免共享便利适配器将坏集合吞成空数组。当前后端 `total` 是限额之后的本次返回计数，页面不把它作为完整账本总量。健康与服务读取使用原有包装函数；它们暂不支持中断参数，因此组件的 generation 校验仍负责丢弃迟到结果。历史运维和日志入口继续提供原有功能。

## 读取生命周期与布局

每个读取状态保留上次成功值、当前请求身份和错误状态。刷新和离开页面会使旧请求失效；`AbortController` 与 generation 双重校验阻止迟到成功或失败覆盖当前事实。请求失败保留成功快照并明确标旧，初次失败不生成零值。严格合同校验区分真实空集合与缺失、重复身份或不合法值。

布局使用计划指定的深蓝底色 `#0C1B2A`、工作区 `#132B3E`、线条 `#29485C`、正文 `#E5EDF4`、次要文字 `#A2B8C9` 和蓝色强调 `#69B4E4`。中文与英文数值使用思源黑体和 IBM Plex Sans 字体栈，哈希使用等宽字体。表格在自身区域内横向滚动，网格使用 `min-width: 0`；390、768、1440、1920 宽度通过断点重排。按钮、链接、筛选和滚动区有可见键盘焦点。真实视口和辅助技术验收由父级统一执行。

## 验证与未完成边界

数据解析与刷新生命周期已覆盖真实空结果、未知计数、错误合同、重复身份、倒置或无效时间、同步错误计数、旧值保留、迟到响应与卸载。挂载测试覆盖清单事实、四项未知质量、精确筛选、证据侧栏、失败刷新和页面只读操作；传输边界测试核验认证守卫、实际 GET 与损坏原始响应。运维测试覆盖服务统计一致性、空事件、组件状态、后端负年龄时钟偏差、事件投影、筛选身份和迟到请求。测试先在占位实现上观察 RED，再实现 GREEN。

2026-11-16 集中运行两个工作区的 6 个测试文件，48 项测试通过，包括历史 hash 入口的回归用例；两目录 12 个源文件格式检查和范围内差异检查通过。应用 TypeScript 检查此前通过；合入并行页面后的最新检查仅报告研究页测试一处可能未定义的访问，交由该页面的父级集成处理。最终类型、完整单元测试、构建和四种真实视口验收由父级统一记录。

本切片不提供完整性检测引擎、质量批准、账户 writer 租约、真实交易门禁、资金对账、恢复演练或不可变归档。这些后端证据必须由各自权威模块提供，页面不会从服务健康推断它们已经成立。
