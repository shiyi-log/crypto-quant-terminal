# 认证与系统页重构

2026-11-16。本小节按全栈重构计划的环境边界、深海蓝视觉和错误状态协议重新实现访问入口；认证服务、会话存储与路由守卫继续承担真实权限判断。页面布局不会授予交易或策略上线资格。

## 登录与本机恢复

- `layouts/auth.vue` 使用终端访问范围与真实认证表单的双区布局，明确登录身份与交易账户的区别；窄屏压缩为说明栏和单列表单。
- 用户名密码表单把实际输入交给既有 `authStore.authLogin`。不自行生成令牌、伪造成功、改变原始返回目标或选择交易账户。
- 本机自动登录继续沿用服务端来源检查；主动退出标记 `ft_manual_logout` 和会话失效标记 `ft_session_expired` 会抑制自动尝试。显式本机登录失败保留手动表单和错误说明。
- 本机恢复只在明确提交后调用现有 `/auth/reset-password`。`/auth/login?recovery=local` 只打开恢复说明，不发送重置请求。恢复结果必须匹配提交时的用户名、随机生成标记和有界密码格式；不确定回执显示可能已执行而不能确认。结果只保留在当前视图，返回登录、路由变化或卸载后清除，不写入日志、存储或 URL。旧密码失效的后果在按钮前说明。
- 正在提交时阻止重复动作；组件卸载或恢复参数变化后忽略迟到结果，但不声称已取消服务端请求。未知错误只显示安全说明，不能把上游原始诊断或凭据反射到页面。用户名、密码、本机入口的副作用仍由现有服务端与认证 store 管理；页面不会把本机访问说明当作身份认证依据。

## 明确退役的模板功能

`code-login`、`qrcode-login`、`register`、`forget-password` 原有模板没有真实的验证码、二维码认证、注册或邮件恢复服务。四个历史路径保留为说明页，给出用户名密码登录与本机恢复链接，并保留已有 `redirect` 返回目标。它们不再展示无效表单、假验证码或成功结果，也不发送认证请求。

## 系统错误页

404、403、500、离线和尚未开放页面共享新的 `SystemState.vue`，分别说明地址不存在、权限不足、读取异常、连接中断和功能不可用。当前地址只以纯文本显示路径与片段，不反射查询参数中的错误文案。

500 和离线页面的重试只重载原地址，不重发业务命令。其他页面的历史返回同时校验标签页路由位置和应用内前一路径；无法确认时返回交易台。页面读取失败和网络恢复都不能证明交易停止、撤销或完成，界面保留这个事实边界。

组件完成不等于路由全部上线。原项目只有全局 404 接线；新增系统路由由主代理统一维护，并在生产构建后进行真实浏览器核验。

## 视觉与验证

使用计划颜色 `#0C1B2A / #132B3E / #29485C / #E5EDF4 / #A2B8C9 / #69B4E4`、文本层级、可见键盘焦点、局部换行与减少动态效果偏好；没有外站字体依赖。字体优先表包含 IBM Plex Sans 和思源黑体，实际字体安装/自托管情况仍由应用全局资源统一管理。

挂载测试覆盖实际表单输入、错误和密码清理、主动退出、会话失效、本机自动登录失败、本机恢复的明确提交和结果清理、未支持方式无表单/请求、返回目标、认证布局实际 RouterView，以及五种系统状态的重试与安全返回。测试隔离真实认证网络边界，不触碰真实账户或凭据。完整前端套件、生产构建与 1920/1440/768/390 浏览器验证由整合阶段统一执行。
