## 0. 为什么需要这份文件

目标要求「前向验证…用实盘数据裁定」。裁定必须有**事先定义的规则**，否则：
- 结果好 → 说「再跑跑看」（继续拖）
- 结果差 → 说「样本不够」（继续拖）
- 29 个策略里总有几个偶然为正 → 挑那个报「找到策略了」（多重比较陷阱）

**本文件把「需要多少样本、什么条件杀掉、什么条件保留」在数据产生前固定下来。**

## 1. 决策规则（三条，事先固定）

对每个策略，在样本达到门槛时按下列规则裁定：

| 判据 | 阈值 | 动作 |
|---|---|---|
| **样本不足** | 平仓笔数 < N_min（见 §2） | **不动**，继续积累。禁止下任何结论。 |
| **杀掉（KILL）** | 样本 ≥ N_min **且** 净收益均值 ≤ 0 | **淘汰**，记入 `explored_and_rejected`，写明样本量与置信区间 |
| **保留（KEEP）** | 样本 ≥ N_min **且** 净收益均值 > 0 **且** bootstrap 95% CI 下界 > 0 | **保留观察**，仍标 `hypothesis`，**不等于可用** |
| **灰色（UNDECIDED）** | 样本 ≥ N_min **且** 均值 > 0 但 CI 含 0 | 记录为「不显著」；**不得**声称有边缘 |

**禁止事项（写入纪律）**
1. 禁止在样本 < N_min 时声称「有信号」或「没信号」。
2. 禁止从 29 个策略中挑选事后表现最好的那个并单独报告（多重比较）。
3. 禁止用「历史回测也支持」来补强前向不显著的结果。
4. 禁止把 KEEP 表述为「盈利/可用/通过」——只有通过人工闸门才能上线。

## 2. 样本量门槛 N_min（按目标单笔效应量推导）

判据：要在双侧 α=0.05、功效 80% 下检出「单笔净收益 = δ（占名义的百分比）」，
近似需要 `N ≈ (2.8 / (δ/σ))²`，其中 σ 为单笔收益标准差。

**实测参考（来自已平仓的 100x 样本）**：单笔收益/保证金约 −0.37，σ 量级很大。

| 目标效应 δ（占名义） | 单笔 USDT（名义 9,259） | 需要样本 N_min |
|---|---|---|
| 0.05% | ≈ 4.6 USDT | ≈ 3,100 |
| 0.10% | ≈ 9.3 USDT | ≈ 780 |
| 0.20% | ≈ 18.5 USDT | ≈ 195 |
| 0.50% | ≈ 46 USDT | ≈ 32 |

**采用值：N_min = 100 笔/策略**（对应约 0.28% 单笔效应、≈26 USDT/笔）。
理由：这是「值得为它占用资金与注意力」的最小经济意义阈值。
**若某策略在 100 笔时仍无法给出 CI 不含 0 的结果 → 按 §1 判 UNDECIDED，不得保留为候选。**

## 2b. ⚠️ 分层裁定（2026-10-12 修订 · 因为原 N_min 未与「可达样本」对齐）

**这是一个我原先漏掉的校验：定 N_min=100 时，我没有检查样本积累速度能否达到它。**
2026-10-12 实测各周期的触发频率后，发现必须分层：

| 周期 | 币数 | 触发/币/年（实测） | 合计/年 | 达 N_min=100 需 | 裁定定位 |
|---|---|---|---|---|---|
| **15m** | 2 | 228~987 | 456~1,974 | **0.1~0.2 年** | ✅ **可做统计裁定** |
| **1h** | 3 | 3~5 | 9~15 | 6.7~11.1 年 | ⚠️ 降为**描述性观察**（不做显著性裁定） |
| **1d** | 3 | 0.5~8 | 2~24 | 4.2~66.7 年 | ⚠️ 仅**机制验证**（看方向，不看显著性） |

**修订后的裁定口径：**

- **15m 策略**：按 §1 三条规则正常裁定（KILL / KEEP / UNDECIDED），N_min=100。
- **1h 策略**：**不做显著性裁定**；只报告累计笔数、均值、方向命中率，标注「样本不足以裁定」。
- **1d 策略**：**仅机制验证** —— 只回答「信号方向是否与预期一致」，不回答「是否显著为正」。

> ⚠️ 1h 的触发频率来自 60~185 个回放点的稀疏采样，噪声大，仅取数量级。

**由此暴露的真实困境（需用户知悉）**：
唯一能在合理时间（1~3 个月）内得出统计结论的周期是 **15m**，
而我早先的参数扫描显示 **15m 上 0 组正样本外净收益**；
可能有边际的 **1h/1d** 在三币池下**无法在合理时间内裁定**。

**三条可能解法**（待用户选择，已提交）：
- **A** 接受分层：只对 15m 做统计裁定，1h/1d 做机制验证
- **B** 提高 1h/1d 触发频率（缩短持有期 H 或放宽阈值）—— 会改变机制本身
- **C** 放宽币池（1h/4h 有 15 币可用，触发频率约 ×5）—— 与用户「只研究三币」冲突

> ⚠️ 上表的 N 是近似值，最终以 bootstrap 置信区间为准，不以点估计为准。

## 2c. ⚠️ 禁止的度量方式（2026-10-12 补充）

**❌ 禁止用「28 个策略里有几个赚钱」作为边缘的度量。**

原因（2026-10-12 实测）：多个策略可以在**同一时刻、同一价格、以相反方向**入场
（例：s17 做空 BTC@83,375.80 与 s02/s20 做多 BTC@83,375.80）。
账户间盈亏会互相抵消，因此「有几个赚钱」主要由**方向分布**决定，而不是由**边际**决定。

**✅ 正确的度量**：每个策略**相对它自己的零假设**——
净收益均值是否 > 0、bootstrap 95% CI 是否不含 0、Bonferroni 校正后是否仍显著。

**⚠️ 同时禁用「跨账户对冲后看总盈亏」** —— 那衡量的是方向净敞口，不是边缘。

## 3. 样本积累速度的约束（已知瓶颈）

**已核对的事实**（2026-10-12）：
- 29 个受管账户中 **24 个从未开仓**（运行 <1 天，属预期）
- 已开仓 7 笔中 **BTC 5 笔(71%)、ETH 2 笔(29%)**
- 两笔已平仓都是 **BTC 空头**，在**同一根 K 线**被同一波 +0.34% 打掉

**结论**：所有策略的 `execution_universe` 都是 [BTC, ETH]，风险敞口高度重叠。
**「29 个策略」的有效独立样本数远小于 29**，接近 1~2 个独立实验。

**因此**：
- 按当前设计，单个策略达到 N_min=100 需要**很长时间**；
- 且样本彼此相关 → 实际标准误大于独立样本假设 → **有效 N 进一步缩水**。

**待 Codex 决策的缓解措施**（已在 `dsh-correlated-accounts-20261012` 提出）：
把 `execution_universe` 从 2 币扩展到 8~20 币。同一信号在 20 币上 ≈ 20 个近似独立样本。
代价：需放宽 `max_positions`（会改变风险敞口），因此由 Codex 判断。

## 4. 多重比较的处理（事先声明）

同时运行 29 个策略 → 即使全部无效，也预期有约 `29 × 5% ≈ 1.5` 个在 α=0.05 下偶然「显著」。

**处理方式**：
1. 报告**全部** 29 个的结果，不允许只报选中的。
2. 若某策略 CI 不含 0，同时报告 **Bonferroni 校正阈值**（α/29 ≈ 0.0017）下的结论。
3. 任何单一策略的「显著」在**独立复现前**一律标 `provisional`。

## §10 机制聚类裁定（2026-10-12 新增 · 解决样本瓶颈）

### 10.1 为什么需要这一条

```
困境: 单策略裁定需要 N_min=100 笔；而 3 币约束下
      · 15m 策略可达（数月）· 1h 需 6.7~11.1 年 · 1d 需 4.2~66.7 年
→ 若只做单策略裁定，绝大多数策略【永远无法裁定】
```

### 10.2 ⚠️ 先说清它**不是**什么（避免与已有禁令冲突）

- **不是**「28 个里有几个赚钱」（那是选择偏差，§2c 已禁止）
- **不是**把不同机制的样本混在一起
- **不是**放宽显著性门槛
- **不是**事后挑选看起来好的族

### 10.3 ⚠️ 统计陷阱（必须先解决，否则规则本身是自欺）

```
朴素做法（错）: 把族内 5 个策略 × 3 币的成交直接合并 → 看似 N ×15
问题: 这 5 个策略在【同一时间、同一币】上交易 → 成交高度相关
      → 有效样本量远小于名义样本量 → 【虚增显著性】

更隐蔽的问题: 同一币在不同策略间的同期相关性 ≈ 1
      （例如 s13/s22/s23 都做 1d BTC 趋势突破，常常同时入场）
```

### 10.4 ⚠️ 我第一版方案是错的（附实测证据）

**第一版草案：把族内成员【等权合成一个组合】，再检验组合的权益曲线。**

实测（15m BTC · 4 个趋势/反转成员）：

| 口径 | 成交数 | 说明 |
|---|---|---|
| 成员成交之和 | 23,854 | 简单相加 |
| **族组合（我原草案）** | **470** | ❌ **最差** |
| 单个最快成员 | 9,625 | |

**⚠️ 为什么错：** 等权合成会把**相关但方向相反**的成员**相互抵消**
（s03 做多时 s05 做空 → 组合仓位近乎不动 → 成交极少）。
**族组合 169 笔/年，比单个成员（3,465 笔/年）慢 20 倍。**
→ **合成组合不但不加快裁定，反而大幅变慢。**

### 10.4b ✅ 修正后的正确做法：合并成交 + 聚类稳健标准误

**不要合成组合。** 而是把族内成员的成交**全部合并**，再用**聚类稳健标准误**校正相关成交。

实测（15m BTC · 同机制 5 个不同参数）：

```
合并成交总数:            25,855 笔
毛均/笔:                 +0.00652%
净均/笔（扣 0.04%）:     -0.03348%

朴素 SE（假设独立）:      0.00648%   ← 会虚增显著性
按天聚类稳健 SE:          0.01347%   ← 正确
【设计效应】= 4.3
→ 有效样本量 = 25,855 / 4.3 ≈ 【5,982】
```

**对比三种口径的裁定能力：**

| 口径 | 有效样本 | 判定 |
|---|---|---|
| 族组合（原草案） | 470 | ❌ 最差 |
| 朴素合并（不校正） | 25,855（虚增 4.3 倍） | ❌ 假显著 |
| **合并 + 聚类稳健 SE** | **≈5,982** | ✅ **正确** |

**⚠️ 关键纪律：设计效应【必须实测】，不得假设。**
本族在 BTC/15m 上测得 4.3；不同族、不同周期会不同。
每次族级裁定必须落盘：**合并样本数 · 朴素 SE · 聚类 SE · 设计效应 · 有效样本量**。

### 10.4c 具体做法

1. **族定义事前固定**（见 10.5 表）
2. **合并**族内成员在**同一币、同一周期**上的成交（不合成组合）
3. **聚类稳健 SE**：按【时间块】聚类（如按天，块长 ≥ 平均持仓期）
   - 同一时间窗内的成交视为一个聚类
4. **有效样本量** = 合并成交数 / 设计效应
5. **多重检验校正**：检验次数 = 族数（**6**），用 Bonferroni 或 BH
6. **判决口径**：见 10.6

### 10.4d 为什么这样能加快裁定

```
单策略:      需要自身 N_min=100 笔
1h 策略:     触发率 5 次/年/币 → 需 6.7~11.1 年
族级合并:    同族 11 个成员 × 3 币 = 33 条序列的成交合并
             → 有效样本可达数千 → 【数月内可裁定】
且检验次数从 29 降到 6 → 多重检验惩罚更轻
```
### 10.5 ⚠️ 这一条**不替代**单策略裁定

- 族级裁定只能回答「这个机制方向是否值得继续」
- **不能**回答「这个具体策略是否可上线」——后者仍需单策略 N_min=100
- 任何「族显著 → 直接上线族内所有策略」都是**越过人工闸门**，禁止

### 10.6 效力与限制

**效力**
- 把 3 币约束下的裁定时间从「数年」压到「数月」
- 用事前固定的族定义避免事后挑选
- 用族组合避免相关成交虚增样本

**限制（如实记录）**
- 族内成员的**机制同一性**是主观判断；若某族实际混了不同机制，族级结论不适用

## §11 成本门槛的精确条件（2026-10-12 修正）

### ⚠️ 我原来的写法不精确

我曾写：「若边际在 maker 口径下 < **2×成本差**，则 taker 口径下必然为负 → 该配置不计入」。

**Codex 指出该写法有问题，我核实后确认它是对的：**

1. **「2倍」只在下述条件同时成立时才有该含义**：
   「成本差」定义为**每边费率差**、名义分母一致、固定尺寸、且**进出名义近似相等**。
2. **若「成本差」已是完整往返费用，再乘 2 会【重复计算】。**
3. **不能拿 USDT 净收益与无名义分母的百分比直接比较。**

### ✅ 精确条件（采用 Codex 的派生式）

对腿 i，冻结数量 `q_i`，实际进出代理成交价 `E_i`、`X_i`，毛收益 `G_i`：

```
P_i(f) = G_i − f × |q_i| × (E_i + X_i)
P_taker = P_maker − Σ_i [ (f_taker − f_maker) × |q_i| × (E_i + X_i) ]
```

**即：maker 净收益小于「这笔实际追加费用」时才必然转负；等于它则刚好为零。**

单腿以**入场名义**归一化时，追加费用为 `Δf × (1 + X/E)`：

| E | X | 1 + X/E |
|---|---|---|
| 100 | 100 | **2.0000** ← 我的「2×」仅在此成立 |
| 100 | 95 | **1.9500** |
| 100 | 110 | **2.1000** |

**→ 2Δf 只是近似。**

### 参考量级

- `maker 0.0002 → taker 0.0005`：单腿往返**近似多 6 bp**
- `→ stress 0.001`：近似多 **16 bp**
- 两腿各有同样名义时，往返共四笔成交，费用 ≈ `4Δf × 单腿名义` 或 `2Δf × 两腿入场总名义`

### ⚠️ 用法限制（Codex 的限定，我接受）

**它只能用来标记「成本脆弱性」，不能自动淘汰配置，也不能证伪整个机制族。**
成本门槛是**筛查**，不是**判决**；判决仍走 §2 / §7 的裁定流程。
